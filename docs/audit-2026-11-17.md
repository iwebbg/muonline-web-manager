# Manager audit — 2026-11-17

Reviewed the manager's installation/resume, configuration changes, backup/update,
process transport, renderer state, administrator operations, release verification and
IPC boundaries. The sibling Laravel project was a read-only reference. No production
service, SQL database or CDN object was changed.

## Confirmed defects fixed

| Priority | Trigger and previous behavior | Result after correction |
| --- | --- | --- |
| P1 | Initial IP/HTTP setup validated consent, then discarded it; the final access step rejected the installation | Finish/Resume reuses consent already validated before the IP configuration was persisted; new IP changes still require explicit consent |
| P1 | Update copied `.env`, then rebuilt it from initial state, overwriting a rotated APP_KEY and custom settings | Update and pre-migration recovery keep the actual `.env` bytes. Access changes alter only manager-owned URL/cookie keys, preserving unrelated values, comments and quoted multiline values |
| P1 | Failed access changes regenerated configuration instead of restoring the backup | Restore the exact `.env`, Compose, nginx and state files; restore PHP ownership of `.env` |
| P1 | Manually changed SQL targets/profile could cause backup/update to use stale recorded database names | Compare resolved Compose SQL targets/profile with saved installation before staging/maintenance and again before backup; refuse drift and DB_URL overrides. Password changes remain allowed |
| P2 | An SSL setup could enable renewal then fail, leaving a timer active; recovery failure could leave a ready state | Restore renewal policy, disable a newly enabled timer after failed initial SSL, and attempt to persist `access-recovery-required` if recovery fails; Start/update stay blocked pending manual recovery |
| P2 | Access form initially selected Local even for an installed IP/domain deployment | Populate current saved mode/host/email. Language switching still preserves unsent edits |
| P2 | Start/Stop/Restart left displayed service status stale | Refresh status after the operation |
| P2 | UTF-8 output decoded separately per OS pipe chunk could corrupt Cyrillic identity names | Decode the stdout stream across chunk boundaries |

The `.env` patch does not attempt to repair malformed unrelated dotenv input: it fails
without replacing the file when a quoted value is unterminated. It never prints its
contents. Configuration restoration is separate from database recovery; no automatic
migration rollback was added.

## Operational boundaries

Real Windows WSL setup, UAC, scheduled tasks, native firewall/service changes, production
SQL bootstrap and public DNS/ACME were not exercised by this Linux audit. Follow the
[Windows VM checklist](windows-vm.md) and [SQL acceptance checks](sql-troubleshooting.md)
for those paths. Existing tests/mock contracts do not establish those Windows results.

A SQL target/profile drift error requires checking the intended databases before
continuing. Restore the relevant target/profile fields from a known-good configuration,
or plan the database move separately with backups. Do not rewrite state.json simply
to suppress the check. A backup/update must not silently act on different databases.

An `access-recovery-required` installation retains the private access backup path in
state. Inspect the backed-up configuration, restore a matching set of files and verify
service health before correcting the phase. Storage failures can prevent recording
the phase itself; the error still identifies the intended private backup directory.
